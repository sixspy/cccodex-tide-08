# 潮位报文归集台

港务水文组收到各潮位站的定长报文。归集员把一批报文贴进来，系统按站码和时刻解析、去重，能落库的写入归集表，列数不对、站码坏了或时刻已经存在的行单独列出。

## 坏行收口与回滚

一批里中途冒出坏行时，已写入的行怎么处理必须事先说死。每天先在「回滚设置」页定死当日收口，写进策略页后本日不得更换；回滚事务还没落地时，设置也不准再碰。

| 收口值 | 收口名 | 行为 |
|--------|--------|------|
| `rollback_all` | 整批收回 | 一批里只要有坏行，已落库的行整批回滚，坏行仍进未接纳队列 |
| `keep_good` | 逐行留下 | 坏行单独进未接纳队列，其余行照常入库 |

- 当日没有定死收口就归集，接口直接 400 拒绝。
- 收口和历史回滚事件对不上（跨天换过收口）时，回滚列表与详情标「回滚收口不符」。
- 同一批原文（按非空行归一后的内容指纹判定）两路同时提交：先拿到指纹锁的那次做回滚，另一次不回滚，只建一条「回滚争用」记录并返回 409。
- 空行不算坏行，归集时跳过且保留原文行号。
- 归集事务持全局咨询锁直到提交，期间回滚设置无法改动。

页面分四块：归集台（贴报文、批次详情）、回滚列表（收回行数／留下行数／收口名）、回滚设置（当日收口）、未接纳队列。回滚详情能看到回滚前后的落库差和收回行快照，整批收回与逐行留下分色区分。

## 接口

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/api/rollback/settings` | 当日收口与当前生效收口 |
| PUT | `/api/rollback/settings` | 定死当日收口（仅归集员，当日一次） |
| GET | `/api/rollback/events` | 回滚列表（含争用、不符标记） |
| GET | `/api/rollback/events/{id}` | 回滚详情与回滚前后落库差 |
| GET | `/api/rejects` | 未接纳队列 |
| GET/POST | `/api/batches` | 批次列表／归集一批 |
| GET | `/api/batches/{id}` | 批次详情（落库行、收回快照、收口事件） |

## 技术栈

| 层 | 选型 |
|----|------|
| 接口 | Python FastAPI |
| 页面 | Vue 3，无组件库 |
| 数据库 | PostgreSQL 16（咨询锁做归集互斥与设置保护） |

## 启动

```bash
cd projects/01-tide-telegram-intake
docker compose up --build
```

健康检查：`GET http://localhost:8211/api/health`

## 种子数据

| 批次 | 结果 |
|------|------|
| 吴淞口 11-12 早班 | 三行都已归集 |
| 外高桥 11-12 错报 | 一行新站落库，一行时刻重复，一行站码不合法 |

种子库同时写入一条当日「逐行留下」收口，便于直接体验；正式归集前请在回滚设置页确认当日收口。

报文每行四段，用竖线分开：站码、十二位时间、潮位厘米、质量旗。质量旗 A 是实测，M 是插补，B 是可疑。
